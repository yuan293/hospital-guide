## 三、分项评分与理由

### 1. 问题与场景价值（15 分）→ **12.5 分**（无变化）

**维持高分**
- 一手调研扎实：N=88，94.3% 近一年"不知道挂什么科"、92.0% 有挂错号/退号重挂；调研"用户最担心的三件事"（推荐错科室 93.2%、急症被耽误 76.1%、隐私泄露 42.0%）与产品的"安全闸门 + 全本地不出网 + 拿不准转人工"设计**一一对应**。
- 场景收窄得当（只解决"挂哪个科"），符合赛题"小切口"导向。

**扣分点（未变，仍是本项唯一瓶颈）**
- 调研与可用性测试均为**团队自采、非第三方**，样本小（N=88/N=8），仅有 docx 在仓库内。
- 缺"问题严重性"的**外部量化佐证**（公开报道的挂错科事件、脱敏退号率等）。

**提分动作**：补 2–3 条外部质性佐证（公开报道/导诊台访谈摘要）；把 N=88 三问做成"问题—证据—边界"一页图。

---

### 2. 创新性与方案设计（20 分）→ **18 分**（+1）

**支持高分（含本次新增）**
- 核心是**架构级创新**：规则守底线 / 模型接多样性 / 不一致由人接管，且用**消融实验**给证据（8 条口语主诉：纯规则 0/8、无模型动态追问 5/8、有模型 8/8）。
- **映射锚点表**（逐词白名单，四类接受规则）——不是拦截错误，而是让错误**结构性不可表达**。
- **润色通道解耦**：协议层 schema 只有 `title`/`description`，结构里根本没有科室/权重；只润色鉴别追问，红旗征与部位问句永不润色。
- **本次新增 → 差异化有了真实对标**：`docs/横向对比-创新性差异化论证-2026-10-03.md` 与 **Triage-Assist-AI**（ED 分诊指挥台）、**Intelligent-guidance**（中文导诊）做了三方结构对照，提炼出四条可辩护创新点，**每条都有代码/数据支撑**。这直接消解了 v2 的"差异化偏自证"扣分点。

**仍扣 2 分的原因**
- 模型能力上限仍受"拒走弃权"约束（意译型口语被拒），创新集中在**安全**而非**理解力**。
- 横向对比已做，但**尚未写进正式技术报告**（报告本身缺失），评委在提交材料里看不到。

**提分动作**：把横向对比压成技术报告里的 1–2 页；把"锚点表 + 润色闸门"抽成**可复用方法**并说明可迁移场景（客服意图分类、工单路由）。

---

### 3. AI 与开源融合（20 分）→ **19 分**（无变化，最接近满分）

**支持高分**
- AI 作用明确且**必要**：消融数据证明去掉模型覆盖率 94.2%→85.2%、口语组 8/8→0/8。
- 开源选型有说理：Qwen2.5 7B+1.5B 双尺寸、Apache-2.0 与仓库许可一致、**明确说明为何不选 Llama 系**（非商业许可无法满足评委独立复现）。
- 自研边界清晰：`THIRD_PARTY_NOTICES.md` 逐条写明版本/来源/许可/义务/自研内容/合规状态，全部"已核验"。
- 许可义务落实到工程：Ollama v0.34.4 钉版本 + SHA-256 校验、模型许可原文归档、`.runtime/` 因再分发合规风险不入库。
- 融合变**双向**：模型从"入口标准化"扩展到"受控改写追问措辞"，16/16 采纳是可核验计数。

**接近满分但未满**
- 模型侧仍是**通用模型直接调用、零医疗微调**。团队用"刻意不微调"解释（论证合理），但评委仍可能认为 AI 侧技术贡献偏薄——创新几乎全在"如何约束模型"。
- AI 工具使用说明（附件1 第（七）条）已在 `THIRD_PARTY_NOTICES` 披露，但**未放进技术报告显著位置**（报告缺失）。

**提分动作**：把 AI 工具使用说明提到报告显著位置；再补一个"模型参与度"增益点。

### 4. 实现完成度与可验证效果（25 分）→ **21.5 分**（+0.5）

**支持高分（第二强项）**
- **真能跑**：本机实测 60/60、data:validate 通过、evaluate 完整跑出 rules/dynamic 两组指标，与 README 完全一致。
- **效果数据成体系**：六组同场评测，含覆盖率、准确率、急诊召回/误触发、弃权率、分歧率、证据失效率；**自动推荐准确率 100%、错误推荐 0**。
- **安全可核验**：急诊召回 12/12、漏诊 0；普通症状误触发急诊 0；红队 24 条三层不安全输出均为 0。
- **盲测对冲 + 防漂移 + CI**：20 条 held-out（实测全绿）、12 文件 sha256 指纹、GitHub Actions 在 ubuntu+Node20 自动跑单测/校验/评测/红队/白名单门禁。
- **本次新增 → 有了"对比结果"**：`docs/同类开源项目调研-2026-10-03.md` 用**可复现的 GitHub API 数据**证明该赛道同类项目普遍 0–5 Star、无评测体系。这使本项目在"对比结果"这一子项上从**空白变为有据**。

**扣分点（本项仍是最大瓶颈）**
- **效果数据仍全是合成工程测试**：README 自己声明"不是临床准确率、不是独立盲测"，主集 130 条与规则共同演进，存在同源过拟合。
- **无上游社区贡献记录**（Issue/PR/补丁）——细则里"社区贡献记录"子项**仍为空**。
- 可用性测试 N=8 与合成评测**两条平行线**，未用真实反馈反向验证评测结论。

**提分动作（性价比最高）**：① 把 N=8 扩成**公开试用 + 30–50 份匿名反馈**，与合成集尾部失败案例（HG-040/041/043/122）**交叉印证**；② 补 1–2 条**真实上游贡献**（哪怕向 Ollama/Qwen 生态提一个文档修正 Issue），把"社区贡献"从 0 变成有；③ 用一张图呈现六组 + 盲测 + 红队的层级关系。

### 5. 开放成果与复用价值（15 分）→ **13.5 分**（+1.5，本次最大提分项）

**支持高分（含本次新增）**
- 成果种类齐全：可运行原型、FHIR R4 Questionnaire 结构、130 条评测集 + 方法学、24 条红队集、门禁与防漂移脚本、本地模型复现模式。
- 权利边界清晰：Apache-2.0 覆盖代码/数据/文档/测试/评测集；`THIRD_PARTY_NOTICES` 逐项标注。
- "单独取用方式"表逐项写出脱离整仓克隆时的取用方法与依赖——复用友好度高。
- 有维护机制：语义化版本、数据版本化、接受勘误但不接受降安全门槛、roadmap #1–#4。
- **本次新增三项**（直接命中 v2 扣分点）：
  1. **公开仓库可访问性已核验闭环**——`visibility: public`、`private: false`、匿名 `ls-remote` 成功（v2 里"唯一但关键的未闭环项"）；
  2. **README 顶部"项目公开地址"区块**——大号直链 + Public 声明 + **3 条评审方可自行复核的匿名命令**，把"公开可访问"从声明变成**可自证**；
  3. **仓库 homepage 已设置 + 10 个 topics 已补**，提升可发现性。

**仍扣 1.5 分**
- **仍无独立发布的可复用包**：所有资产都在主仓库内，第三方复用"评测方法学"或"锚点表"必须克隆整仓。
- 仍缺 `CHANGELOG.md` 与 issue 模板等治理文件。
- 轻微：GitHub 侧 `license.spdx_id` 返回 `NOASSERTION`（LICENSE 文件本身是标准 Apache-2.0，属 GitHub 自动识别问题，不影响法律效力，但观感上略欠）。

**提分动作**：① 把"锚点表 + 评测门禁"抽成**独立小仓库或 npm 包**（零依赖，易抽出），这是最具外溢价值的开放成果；② 补 `CHANGELOG.md`；③ 让 GitHub 正确识别 Apache-2.0。

## 四、优化优先级（按投入产出比）

### P0 — 影响评审第一印象，必须做（当前唯一高危项）
1. **产出技术报告（PDF，≤15 页）**：按《AIC·AI+开源技术报告参考大纲》（附件2）撰写。**把今天新做的"横向对比"和"方向调研"直接编入创新性章节**，把 AI 工具使用说明单列一节。
2. **产出演示视频（MP4，3–5 分钟，≤300MB）**：展示两入口 → 安全确认 → 动态追问 → 弃权转人工 → 模型措辞润色前后对照 → 关怀模式 → 模拟挂号全流程。
3. **答辩 PPT（晋级后提交）**：按细则八要素组织。
*（注意：细则第（九）条——所有评审材料**不得出现学校名称/LOGO/指导教师信息**。）*

### P1 — 直接影响得分档位
4. **补真实用户数据**（N=8 扩到 30–50 份匿名反馈），与合成集尾部失败案例交叉印证 → 冲"实现完成度"23–25 分。
5. **补 1–2 条上游社区贡献**（Issue/PR 均可），填补"社区贡献记录"子项。

### P2 — 打磨与合规
6. **抽出独立可复用包**（锚点表 / 评测门禁）。
7. 补 `CHANGELOG.md`、issue 模板；让 GitHub 正确识别 Apache-2.0。

## 五、如果只优化三件事
