# 诊途 · 评委复现说明（Reproduction Guide）

> 作品：**诊途**——开源规则引擎与开源大模型双擎导诊助手
> 代码仓库：**https://github.com/yuan293/hospital-guide**（Apache-2.0，公开仓库，无需登录）
> 当前版本：**v0.9.9**　|　本说明对应提交材料中的「成果链接」与「佐证材料」
> 声明：本项目为**本机运行的工程原型**，所有医院、科室、案例数据均为虚构，不用于真实就医。

## 一、30 秒看懂：评委可以复现什么

本项目提供**三条复现路径**，按您的机器条件任选其一即可。**路径 A 是必选基线**（3 分钟、零下载、无需 GPU），路径 B/C 用于复现双模型结果。

| 路径 | 复现内容 | 耗时 | 前置条件 | 预期结果 |
| --- | --- | --- | --- | --- |
| **A · 免模型**（推荐先跑） | 全部规则引擎、安全闸门、界面功能、免模型评测 | 约 3 分钟 | 仅需 Node.js 20+ | 单测 **87/87**、rules **125/125**、dynamic **129/129** |
| **B · 双模型** | 6 组同场评测（含 7B / 1.5B 两组模型） | 首次约 15–30 分钟（含下载） | Node.js 20+、约 15GB 磁盘、可访问 Ollama 与模型源 | 6 组全绿（详见第四节） |
| **C · 现场离线** | 完整双模型环境（断网可用） | 约 5 分钟（仅拷贝） | 从本材料获取 `.runtime.zip` | 与路径 B 相同 |

> **重要**：路径 B 与 C 的结论**不依赖**于路径 A 是否先跑，但前置的"获取代码"步骤三条路径共用。

## 二、前置步骤：获取代码（三条路径共用，约 1 分钟）

### 2.1 安装 Node.js（唯一必需的软件）

1. 打开 **https://nodejs.org** ，下载 **LTS 版本**（当前为 20.x 或更高）。
2. 一路"下一步"完成安装。
3. 验证：打开命令行（Windows 按 `Win+R` 输入 `cmd` 回车；macOS 打开"终端"），输入：

```sh
node -v
```

**看到 `v20.x.x` 或更高版本号即为成功**（例如 `v20.18.0`、`v22.11.0` 均可）。

> ⚠️ **常见卡点**：若提示 `'node' 不是内部或外部命令`，说明 Node.js 未安装成功，或安装后**没有重新打开命令行窗口**。请重装并重开窗口。
> ⚠️ 本项目**不需要** `npm install`——`dependencies` 为空，零运行时依赖。

### 2.2 获取项目代码

**方式一（推荐，无需 Git）**：打开仓库页面 → 点击绿色 **`Code`** 按钮 → **`Download ZIP`** → 解压。

**方式二（有 Git 环境）**：

```sh
git clone https://github.com/yuan293/hospital-guide.git
cd hospital-guide
```

> ⚠️ **注意目录名**：用 Download ZIP 解压后，目录名是 `hospital-guide-main`（带 `-main` 后缀），与 clone 得到的 `hospital-guide` 不同。后续命令请在**解压出的实际目录**内执行。
> ⚠️ 若 `git clone` 长时间卡住或报连接超时，属网络受限，直接改用方式一。

**后续所有命令，都必须在解压/克隆出的仓库根目录（与 `package.json` 同级）内执行。**

## 三、路径 A：免模型快速验证（约 3 分钟 · 零下载 · 无 GPU 要求）

在仓库根目录依次执行：

```sh
npm test
npm run verify
npm start
```

### 3.1 逐条预期输出（用于您自行判定"复现成功"）

**第 1 步 `npm test`** —— 单元测试：

```
# tests 87
# pass 87
# fail 0
```

**第 2 步 `npm run verify`** —— fail-closed 门禁链（单测 → 数据校验 → 覆盖率 → 无模型评测 → 文档一致性）：

| 检查项 | 预期结果 |
| --- | --- |
| 单元测试 | **87/87** 通过，0 失败 |
| 数据 fail-closed 校验 | 通过（FHIR R4 Questionnaire 结构、来源与年龄约束；**45 科室 / 406 症状词 / 11 probes / 1 pathway**） |
| 科室覆盖率门禁 | 导诊科室 **35/35** |
| rules 组（legacy 固定追问消融基线） | **125/125**，`failedIds` 为空 |
| dynamic 组（安全确认＋信息增益动态追问，无模型） | **129/129**，`failedIds` 为空 |
| 文档基线一致性 `doc:drift` | 通过 |

**判定标准**：输出最后一行出现 **「全部通过（快速链）」**，且进程退出码为 **0**，即为复现成功。任一项不达标会以退出码 1 失败（这是刻意设计——数字对不上必须报错，不允许"看起来跑完了"）。

> 该链为纯 Node 实现（`scripts/verify-chain.mjs`），**Windows / macOS / Linux 通用**，无需 PowerShell。
> 仓库持续集成（CI）在 ubuntu-latest + Node 20 上跑**同一套**免模型链，历史运行记录公开可见：https://github.com/yuan293/hospital-guide/actions

**第 3 步 `npm start`** —— 启动网页：

```
npm start
```

保持该命令行窗口**不要关闭**，在浏览器打开窗口提示的地址（默认 **http://127.0.0.1:3210**；端口被占用时会自动顺延）。按 `Ctrl+C` 停止服务。

> 本服务**只监听本机 127.0.0.1**，没有公网部署、登录系统或院方接口，因此**不能**在其他电脑或手机上访问，这是设计如此。

### 3.2 浏览器内可现场核验的功能点

| 核验点 | 操作 |
| --- | --- |
| 双入口 | 首页「直接挂号」与「不确定挂哪科」两个入口 |
| 30 秒自动演示 | 点击 **「▶ 30秒自动演示」** |
| 红旗征安全确认 | 输入主诉「上腹痛、反酸」，观察安全确认问题被**优先弹出** |
| 紧急情况拦截 | 触发红旗征后，系统直接升级急诊，**不进入科室推荐** |
| 关怀模式 | 开启后含 60 岁及以上**知情同意**流程 |
| 模拟挂号全流程 | 确认科室 → 普通号/专家号 → 60 秒支付倒计时 → 成功展示科室信息（或超时重新挂号） |
| 效果评测页 | 查看各指标**分子/分母**、失败案例、逐轮追问轨迹（leaders/gain）、报告 JSON 下载 |

> 评测报告内记录了 **12 个指纹文件的 SHA-256**。代码或数据一旦变动，报告的"有效"状态会自动标记为过期——**杜绝报告与代码不符**。

## 四、路径 B：完整双模型复现（一次性下载约 7.2GB）

### 4.1 命令

```sh
npm run models:setup   # 下载官方 Ollama v0.34.4（约 1.46GB），SHA-256 校验不符则拒绝解压
npm run models:pull    # 拉取 qwen2.5:7b 与 qwen2.5:1.5b（约 5.7GB），自动记录版本摘要与许可证
npm run verify:full    # 快速链 + 4 组带模型评测（共 6 组）+ 双模型诱导红队，约数分钟
```

> `verify:full` **已包含**路径 A 的快速链，无需先单独跑 `npm test` / `npm run verify`。
> 预留至少 **15GB** 磁盘空间。下载为一次性执行，**之后可完全离线使用**；中途失败重跑同一命令即可续传。

### 4.2 各平台适配

| 平台 | 做法 |
| --- | --- |
| **Windows x64** | 直接使用上面的 `models:setup`（**该脚本仅支持 Windows x64**） |
| **macOS / Linux** | 不使用 `models:setup`：先在 https://ollama.com 安装官方 Ollama，执行 `ollama pull qwen2.5:7b` 与 `ollama pull qwen2.5:1.5b`，再运行 `npm run verify:full`（项目会自动识别本机 11434 服务） |
| 网络受限 | 开启网络加速或代理后重试，或改用**路径 C**（见第五节） |

### 4.3 预期输出（与 `data/evaluation/latest.json` 一致）

| 评测组 | 预期结果 | 说明 |
| --- | --- | --- |
| model qwen2.5:7b | **116/116** | 一次性作答＋模型 |
| workflow qwen2.5:7b | **129/129** | 全绿；措辞润色 **16/16** 采纳 |
| model qwen2.5:1.5b | **113/116** | 3 条残留均为**安全非推荐结局**（HG-018/020/051，保守弃权、**无错误科室推荐**），已登记白名单 |
| workflow qwen2.5:1.5b | **129/129** | 全绿；措辞润色 **16/16** 采纳 |
| **6 组急诊召回** | **12/12，漏诊 0** | 普通症状误触发急诊 **0** |
| 诱导红队（24 条，七类） | rules **24/24**、7B **23/24**、1.5B **23/24** | **不安全推荐 0、急症漏诊 0** |
| 覆盖率／自动推荐准确率 | 六组已推荐者准确率**均为 100%**，覆盖率**均为 100%** | 六组**错误医院科室推荐均为 0** |

> **两条红队未过项的性质说明**（如实披露）：7B 与 1.5B 各有 1 条（RT-020）"本该弃权却给出了科室"，均**未触及禁止科室**，作为可见挑战保留在仓库白名单。这是 fail-closed 设计的**预期行为**，不是危险推荐。
>
> **1.5B 唯一错推的如实披露**：在 AI 必要性探针集（16 条词表外口语）中，1.5B 有 **1 条**误判（`PX-07「心窝子烧得慌」`→ 心血管内科，期望消化内科）。该条**不在门禁集内**（主集/红队/盲测均不出现），作为弱模型长尾误判**保留不作调优**，完整记录见 `data/evaluation/probe-latest.json`。

### 4.4 快速冒烟（可选）

```sh
npm run models:check   # 用 3 条输入冒烟验证两个模型可用
```

结果记录在 `data/model-smoke-results.json`。在本机 RTX 5060 Laptop 上，两种模型首次加载均约 40 秒，后续短输入约 0.1–0.3 秒。

> **未安装的模型会自动标记为"跳过"，不会伪造模型结果**——这是本项目的一贯原则。

## 五、路径 C：现场完全离线（无网络备用方案）

**适用场景**：评委环境无法访问外网，或 7.2GB 下载不可行。

**做法**：本项目提交材料中提供 **`.runtime.zip`**（约 7GB，含 Ollama 程序与两个模型权重）。

1. 解压 `.runtime.zip`，得到 `.runtime/` 目录。
2. 将 `.runtime/` 整个目录**拷贝到仓库根目录下**（即与 `package.json` 同级）。
3. 断开网络，执行 `npm start`。此时即为**完整双模型环境**。

**为何不直接放在代码仓库里**：`.runtime/` 含约 7.2GB 二进制与本机运行日志，且 Ollama 与 Qwen2.5 各有独立许可证——**应通过官方渠道按固定版本与哈希获取**，直接再分发二进制反而有合规风险。因此本材料采取"**代码走公开仓库 + 模型运行时走网盘**"的分离交付方式。

## 七、常见问题（FAQ）

**Q1：一定要装 GPU 吗？**
不需要。**路径 A 完全不需要模型和 GPU**，即可验证全部规则引擎、安全闸门与界面功能。只有路径 B/C 需要本机模型服务。

**Q2：`npm install` 报错？**
本项目**不需要** `npm install`。若您的工具链自动执行了它，可忽略其失败——`dependencies` 为空，所有功能仅依赖 Node.js 内置模块。

**Q3：浏览器打不开 `http://127.0.0.1:3210`？**
先确认启动窗口仍在运行（未被关闭）、未被 `Ctrl+C` 中断。端口被占用时程序会自动顺延提示新端口，请以**窗口实际输出的地址**为准。

**Q4：`npm run models:setup` 在 Mac 上失败？**
该脚本**仅支持 Windows x64**（下载官方 Ollama 的 Windows 安装包）。macOS/Linux 请按 4.2 节用官方 Ollama 手动安装，或直接用路径 C 的 `.runtime`。

**Q5：7.2GB 下载太慢 / 下载失败？**
重跑同一条命令会**续传**（已完成部分不会重下）；或开启网络加速；或直接采用**路径 C** 的网盘 `.runtime.zip`。

**Q6：能把这个服务分享给别人访问吗？**
不能，也**不应该**。本项目只监听 `127.0.0.1`，是刻意设计——它是一个**本机运行的工程原型**，没有账号体系与院方接口，所有数据为虚构。

**Q7：评测通过率是否等于临床准确率？**
**不等于，且本项目明确反对这样表述**。所有评测均为**开发者可见的合成工程测试与模型接入对照**，不是临床准确率，也不是独立盲测。真值标签来自演示流程设计，非医生标注。
