## 一、结论速览

1. **「AI 症状自查 / 智能导诊」这个赛道，真正成熟的开源项目极少。** GitHub `topic:symptom-checker` 全站仅 **124 个仓库**，`topic:triage + healthcare` 仅 **65 个**，且**绝大多数是 0～5 Star 的个人练手/简历项目**，普遍无 License、无测试、无评测集、无 CI、创建即停更。
2. **赛道的商业化主导者是闭源 API**（Infermedica、Endless Medical 等）。开源生态里只有它们的**客户端示例**，没有引擎本身。
3. **诊途的差异化优势在开源生态里相当稀缺**，尤其是以下几点在同类项目中**基本看不到**：
   - 规则先行的**红旗征安全闸门**（急症硬分流，模型不可覆盖）
   - **本地化部署**（零第三方运行时依赖 + 本地 Ollama 模型，数据不出机）
   - **体系化评测门禁**（held-out 冻结盲测集 + 对抗红队集 + SHA-256 指纹防漂移 + 失败白名单）
   - **模型证据核验**（映射锚点表：字面/形态锚点/双语素/登记同义形四规则）
4. **值得参考/对标的"真项目"分三类**：① 成熟开源医疗系统（OpenEMR）；② 医疗 NLP 工具库（MedCAT）；③ 医疗大模型与安全评测框架（MedicalGPT、MING、scribegoat2、HarmBench）。这些**不是同赛道竞品，但是可引用的生态坐标**。

**A 类共性短板（也就是诊途的机会点）**：
- 无一例具备**冻结盲测集 + 对抗红队集 + 指纹防漂移**的评测门禁；
- 极少有**规则先行的红旗征硬闸门**（多数把安全交给模型自觉）；
- 多数依赖云端 API，**隐私本地化**只有少数几个做到；
- 中文医疗场景下，**没有任何一个**提供成体系的评测证据。

## 四、赛道全景小结

```
                     成熟度 →
  闭源商业           Infermedica API · Endless Medical · 各家"AI 自诊"商业产品
  （引擎不开放）      （诊所级临床验证，按调用收费）

  成熟开源           OpenEMR（院内全流程 EHR）· MedCAT（医疗 NLP）· MedicalGPT/MING（医疗大模型）
  （不同层，非竞品）   ← 可引用为生态坐标

  安全评测           scribegoat2 · HarmBench · lumen-clinical
  （方法论）          ← 诊途红队集的对标对象

  应用层同类         诊途？  ← 这个位置几乎全是 0-5 Star 的个人项目
  （症状自查/导诊）   sytora(177⭐/停更8年) · Infermedica示例 · 一堆简历项目
```

**关键发现**：诊途所处的"**应用层 + 安全工程 + 本地化 + 评测门禁**"这个交集，在开源生态里**几乎没有先例**。同类项目要么停更多年，要么无评测无许可，要么把安全交给云端模型。这既是诊途的**创新性论据**，也意味着**没有现成对标物可"抄"，需自己立标准**。
