**变动解读（共 +2.5）：**
- **AI 与开源融合 +1（18→19）**：0.8.0 把"融合"从**单向约束**变成**双向**（模型既做口语标准化，又做受控的追问措辞润色），且用协议层隔离 + fail-closed 核验 + 16/16 采纳计数把"双向"做成了**可核验事实**。这正是上次"提升到 19–20 分"里点名的第 1 条动作，已落地。
- **创新性 +1（16→17）**：00.8.0 的"润色通道独立于证据通道、且只润色鉴别追问、红旗征与部位问句永不润色"是一处**职责解耦**层面的设计创新，不是功能堆砌；可核验计数也优于上次的口头论证。
- **开放成果 -0.5（12.5→12）**：扣分主因是**公开仓库可访问性仍未验证**、独立可复用包仍未抽出，这两项是上次 P2 清单里唯一没有进展的；其余资产项维持。
- **其余三项维持**：问题与场景价值（调研仍是自采 N=88）、实现完成度（效果数据仍以合成为主、无真实使用数据、无上游社区贡献）**没有实质变化**——这两块正是当前最大的提分瓶颈。

**一句话结论**：v0.8.0 是**在"安全工程"这条主线上又推进了一格**的版本，把上次建议的"双向融合"真正做出来了，评分为 82.5/95。但**决定晋级上限的不是代码质量，而是两件仍未动的事**：① 技术报告/演示视频/PPT 完全缺失（评委的第一入口）；② 25 分权重最大的"实现完成度"仍缺真实用户数据与社区贡献记录。

## 二、分项重新评分与理由

### 1. 问题与场景价值（15 分）→ **12.5 分**（无变化）

**维持高分的证据**
- 一手调研扎实：`docs/诊途-问题与场景价值-调研正文.docx`，N=88，**94.3%** 近一年"不知道挂什么科"、**92.0%** 有挂错号/退号重挂；62.7% 靠网上搜、71.6% 最终仍靠导诊台——"痛点普遍 + 现有工具触达不足（73.9% 从未见过智能导诊）"的证据链完整。
- 场景收窄得当（只解决"挂哪个科"），符合竞赛"小切口"导向；调研的"用户最担心三件事"（推荐错科室 93.2%、急症被耽误 76.1%、隐私泄露 42.0%）与产品的"安全闸门 + 全本地不出网 + 拿不准转人工"设计**一一对应**，89.8% 受访者接受该边界（均分 4.26/5）。

**扣分点（未变）**
- 调研与可用性测试**均为团队自采、非第三方**，样本量小（N=88 / N=8），且**仅有 docx 在仓库内**，无公开可访问链接佐证。
- 缺"问题严重性"的**外部量化数据**（如公开报道的挂错科事件、脱敏退号率），价值论证基本靠自采问卷单点支撑。

**提分动作**：把 N=88 三问做成"问题—证据—边界"一页图；补 2–3 条**外部质性佐证**（公开报道/导诊台访谈摘要）；把 N=8 的"卡点→迭代"单独成节。

---

### 2. 创新性与方案设计（20 分）→ **17 分**（+1）

**支持高分的证据（含 0.8.0 新增）**
- 核心仍是**架构级创新**：规则守底线 / 模型接多样性 / 不一致由人接管，且用**消融实验**给证据（8 条口语主诉：纯规则 0/8、无模型动态追问 5/8、有模型 8/8）。
- 0.7.0 的**映射锚点表**（逐词白名单，四类接受规则）是真正的安全工程创新——**不是拦截错误，而是让错误结构性不可表达**。
- **0.8.0 新增的"润色通道解耦"是本次提分点**：协议层 schema 只有 `title`/`description`，**结构里根本没有科室/权重**；只润色鉴别追问，红旗征与部位问句**永不润色**；失败 fail-open 回退配置原文。这是把"模型的第二类职能"做成**协议级不可能越权**，设计成熟度明显高于"加个功能"。

**扣分点**
- 与"常见方案差异"对比表仍**未对标任何真实同类开源项目**，差异化偏自证。
- 模型能力上限仍受"拒走弃权"约束（意译型口语如"耳朵嗡嗡响"被拒），创新集中在**安全**而非**理解力**。

**提分动作**：补 1–2 个真实开源 triage/导诊项目的**结构化横向对比**；把"锚点表 + 润色闸门"抽成**可复用方法**并说明可迁移场景（客服意图分类、工单路由）。

### 3. AI 与开源融合（20 分）→ **19 分**（+1，最接近满分项）

**支持高分的证据**
- **AI 作用明确且必要**：消融数据证明去掉模型覆盖率 94.2%→85.2%、口语组 8/8→0/8；模型位置不可被规则替代。
- **开源选型有说理**：Qwen2.5 7B+1.5B 双尺寸、Apache-2.0 与仓库许可一致、**明确说明为什么不选 Llama 系（自定义/非商业许可无法满足评委独立复现）**——这是很有说服力的选型逻辑。
- **自研边界清晰**：`THIRD_PARTY_NOTICES.md` 10 项逐条写明版本/来源/许可/使用方式/关键义务/自研内容/合规状态，全部"已核验"；且**第 6 项已从旧的"90 条/21 条"更正为 122 条/24 条/20 条冻结集**（上次的高危问题已修）。
- **许可义务落实到工程**：Ollama v0.34.4 钉版本 + SHA-256 校验、模型许可原文归档 `data/model-licenses/`、`.runtime/` 因再分发合规风险不入库——是代码里真实存在的动作。
- **0.8.0 融合变双向**：模型从"只做入口标准化"扩展到"受控地改写追问措辞"，且**16/16 采纳、0 拒收**是可核验计数而非口号。

**接近满分但未满的原因**
- 模型侧仍是**通用模型直接调用、零医疗微调**。团队用"刻意不做医疗微调"解释（论证合理），但按细则"未形成实质改进的原则上不认定充分创新"，评委仍可能认为**AI 侧技术贡献偏薄**——创新几乎全在"如何约束模型"。
- **AI 工具使用说明**（附件1 第（七）条）已在 `THIRD_PARTY_NOTICES` 第 9/10 项披露，但**尚未放进技术报告显著位置**（技术报告本身缺失）。

**提分动作**：把 AI 工具使用说明提到报告显著位置（Codex/Trae 用在哪些环节 + 团队审核修改验证流程）；再补一个"模型参与度"增益点（如歧义主诉的候选置信，仍需过闸门）。

### 4. 实现完成度与可验证效果（25 分）→ **21 分**（无变化，权重最大、瓶颈最明显）

**支持高分的证据（第二强项）**
- **真能跑**：本机实测 `npm test` 60/60、`data:validate` 通过、`evaluate` 完整跑出 rules/dynamic 两组指标，与 README **完全一致**。
- **效果数据成体系**：六组同场评测（rules/dynamic/7B model/7B workflow/1.5B model/1.5B workflow），含覆盖率、准确率、急诊召回/误触发、弃权率、分歧率、证据失效率、平均轮数；**错误科室推荐全部为 0**。
- **安全可核验**：急诊召回 12/12、漏诊 0；普通症状误触发急诊 0；红队 24 条三层不安全输出均为 0。
- **盲测对冲**：20 条 held-out 冻结集，报告内 `dataset.sha256` 可核验未被事后修改；本机实测 rules 组 18/18。
- **防漂移 + CI**：12 文件 sha256 指纹，代码/数据一变旧评测自动标记过期；GitHub Actions 在 ubuntu+Node20 自动跑单测/校验/免模型评测/红队/白名单门禁。
- **三条复现路径**：免模型 3 分钟 / 双模型一次性下载 / 现场离线。

**扣分点（未变，最值得改的地方）**
- **效果数据仍全是合成工程测试**：README 自己反复声明"不是临床准确率、不是独立盲测"，主集 122 条与规则**共同演进**存在同源过拟合。按细则"具有可核验的效果数据、**用户反馈**、对比结果或**社区贡献记录**→18–25 分"，目前只有合成数据 + N=8 小样本反馈。
- **无上游社区贡献记录**（Issue/PR/补丁），细则里"社区贡献记录"子项**仍为空**。
- 可用性测试 N=8 与合成评测**两条平行线**，未用真实反馈反向验证评测结论。

**提分动作（性价比最高）**：① 把 N=8 扩成**公开试用 + 30–50 份匿名反馈**，产出"哪类主诉弃权/转人工最多"，与合成集尾部失败案例（HG-040/041/043/122）**交叉印证**；② 补 1–2 条**真实上游贡献**（哪怕向 Ollama/Qwen 生态提一个文档修正 Issue），把"社区贡献"从 0 变成有；③ 用**一张图**呈现六组 + 盲测 + 红队的层级关系。

### 5. 开放成果与复用价值（15 分）→ **12 分**（-0.5）

**支持高分的证据**
- **成果种类齐全**：可运行原型、FHIR R4 Questionnaire 结构（18 个 StructureDefinition）、122 条评测集 + 方法学、24 条红队集、门禁与防漂移脚本、本地模型复现模式。

## 三、优化优先级（按投入产出比）

### P0 — 影响评审第一印象，必须做（当前最大短板）
1. **产出技术报告（PDF，≤15 页）**：按《AIC·AI+开源技术报告参考大纲》撰写。结构建议：问题与场景 → 方案架构（含安全闸门图）→ AI 与开源融合方式（含 0.8.0 双向融合）→ 自主实现内容 → 效果与验证（六组 + 盲测 + 红队）→ 创新点 → 开放成果 → 后续计划。**把 AI 工具使用说明单列一节**（附件1 第（七）条）。
2. **产出演示视频（MP4，3–5 分钟）**：展示两入口 → 安全确认（"上腹痛、反酸"触发红旗征）→ 动态追问（可见并列科室与增益分）→ 弃权转人工 → **模型措辞润色前后对照** → 关怀模式 → 模拟挂号全流程。视频是最快让评委理解"这套东西真的在跑"的方式。
3. **确认公开仓库在评审期内持续可访问**，并把链接放到显眼位置。

### P1 — 直接影响得分档位
4. **补真实用户数据**（N=8 扩到 30–50 份匿名试用反馈），与合成评测尾部失败案例交叉印证 → 直接冲"实现完成度"23–25 分。
5. **补 1–2 条上游社区贡献**（Issue/PR 均可），填补"社区贡献记录"子项。
6. **横向对比 1–2 个真实同类开源项目**，强化创新性差异化论证。

### P2 — 打磨与合规
7. **抽出独立可复用包**（锚点表 / 评测门禁）。
8. 补 `CHANGELOG.md`、issue 模板等治理文件。
9. 清理根目录遗留的 `server.log` / `server-error.log`（虽然被 `.gitignore` 覆盖，但工作区可见）。
