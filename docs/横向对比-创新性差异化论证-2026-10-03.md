在 A 类同类中，绝大多数是 0 Star 的个人练手项目，**不具备可对比的技术含量**。经筛选，只有两个值得做深度对比——它们分别代表该赛道的两种典型路线：

| 对比对象 | 定位 | 为什么选它 |
| --- | --- | --- |
| **① draculess99/Triage-Assist-AI** | 美国 ED（急诊科）分诊指挥台 | 该赛道中**技术完成度最高**的开源项目：ESI 分级引擎 + 规则闸门 + 护士确认 + 审计留痕 + XAI + RAG + 多智能体。理念与诊途最接近，**是对比价值最高的"强对手"** |

> 注：`infermedica/*` 系列 Star 更高（70⭐），但**引擎闭源**，只有客户端示例，无可对比的引擎实现；`openemr` 是院内全流程 EHR，**不同层**。故不选作主对比。

## 三、核心机制对照（这是差异化论证的主体）

### 3.1 安全兜底：规则闸门的"位置"不同

| | 诊途 | Triage-Assist-AI |
| --- | --- | --- |
| 闸门形态 | **红旗征硬分流**（`redflag` 类型问题，3 条安全确认路径） | 确定性 ESI 引擎 + 红旗征协议检测（卒中/脓毒症/心梗/呼衰/创伤） |
| 问题库标准 | **对齐 HL7 FHIR R4 Questionnaire**（11 条：1 location + 7 differential + 3 redflag） | 自定义结构（`esi_engine.py`） |
| 模型与安全的关系 | 模型**碰不到**急诊结论（输出被 `enum: keywords` 约束在词表内） | 规则引擎与 LLM 分离，LLM 只做辅助（Safety Sentinel 等智能体），不可覆盖 ESI 引擎 |

**结论**：两者都做了"规则优先"，这是该赛道的**正确共识**。差异在下一点。

### 3.2 数据不出机：本地化 vs 云端（诊途的核心差异化）

| | 诊途 | Triage-Assist-AI |
| --- | --- | --- |
| LLM 运行位置 | **本机 Ollama**，模型权重本地（SHA-256 校验） | **Groq / Gemini 云端 API** |
| 患者病情描述流向 | **不出本机** | 发送至第三方云服务 |
| 断网可用性 | 规则全链路可用；模型不可用时 fail-open 到规则 | 无 LLM Key 时降级为本地专家系统 |
| 可部署场景 | 医院内网、无外网环境、隐私敏感场景 | 需外网（虽支持降级） |

**这是诊途最硬的差异化**：医疗场景下"病情描述发送到境外云 API"是合规红线。诊途把模型跑在本地，**从架构上消除了数据外发**，而非靠承诺。

### 3.3 模型"融合"的深度：单向 vs 双向 + 证据核验

| | 诊途 | Triage-Assist-AI |
| --- | --- | --- |
| 模型职责 | **两类受约束职能**：① 口语→标准症状词标准化；② 追问措辞润色（把"系统话术"改写成人话） | LLM 做 RAG 引用、智能体摘要、AI Committee 辩论 |
| 输出约束 | **协议层 schema 约束**（标准化限 `enum: keywords`；润色限 `title`/`description` 两字段，结构里根本没有科室/权重/选项） | 无 schema 级硬约束（LLM 输出进入展示层） |
| 证据核验 | **映射锚点表**（逐词白名单，4 条验收规则：字面/形态锚点/双语素/登记同义形） | 无明显证据核验机制（依赖 RAG 引用降低幻觉） |
| 失败处理 | **fail-closed**（润色含诊断/用药/淡化风险词 → 拒收回退原文） | — |

**关键差异**：诊途的模型是"**被约束的**"——它在协议层就**无法**影响任何评分或安全结论；且每条模型证据要过"映射锚点表"的逐词白名单。Triage-Assist-AI 用 RAG 引用缓解幻觉，但缺少**结构性的证据核验**。

### 3.4 评测门禁：有 vs 无（最悬殊的一项）

| | 诊途 | Triage-Assist-AI | Intelligent-guidance |
| --- | --- | --- | --- |
| 主评测集 | **150 条**（含 6 组对照：rules/dynamic/model×2/workflow×2） | 有 `metrics.json`（模型指标） | **无** |
| 冻结盲测集 | **20 条 held-out**（预先冻结，防过拟合） | 无 | 无 |
| 对抗红队集 | **24 条**（含映射锚点攻击） | 无 | 无 |
| AI 必要性探针 | **16 条**（词表外语料，量化模型增量 · 非门禁） | 无 | 无 |
| 防漂移 | **SHA-256 指纹**（评测集/配置 12 文件指纹，变动即失效） | 无 | 无 |
| 失败白名单门禁 | **有**（失败集需显式登记，新增失败即拦截） | 无 | 无 |
| 覆盖率门禁 | **有**（导诊科室 35/35，未达用例下限须显式声明并反向校验） | 无 | 无 |
| 自动化测试 | **87 个单测**（`node --test`，主仓 71 ＋ 独立包 16）+ CI | 未见测试文件 | 无（交付物以文档为主） |
| 自动评分脚本 | 有（`npm run evaluate` / `redteam`） | 有 ML 指标脚本 | 无 |

**这是诊途最不可替代的资产**：该赛道同类项目中，**没有任何一个**建立了"冻结盲测 + 对抗红队 + 指纹防漂移 + 白名单门禁"的完整评测体系。Triage-Assist-AI 有 `metrics.json` 但那是**模型精度指标**，不是**端到端行为评测**；Intelligent-guidance 完全没有评测。

## 五、差异化论证总结（可直接用于创新性章节）

将上表收敛为**四条可辩护的创新点**，每条都有上述客观数据支撑：

### 创新点 1：规则闸门 + 模型受约束的"安全架构"
- **稀缺性**：同类要么把安全交给模型自觉，要么仅做规则。诊途让**模型在协议层无法影响评分/安全结论**（schema 约束 + 映射锚点表逐词核验）。
- **证据**：`enum: keywords` 约束；润色 schema 只有 2 个字段；`acceptPolish()` fail-closed 黑名单。
- **对比**：Triage-Assist-AI 规则与 LLM 分离，但 LLM 输出无相同层级的协议约束。

### 创新点 2：本地化部署（数据不出机）
- **稀缺性**：A 类同类中，绝大多数依赖云端 API（OpenAI/Gemini/Groq）。做到**本地模型**的仅个别 0-Star 项目，且无评测。
- **证据**：`dependencies: {}` 零依赖；本地 Ollama Qwen2.5 双模型；权重 SHA-256 校验。
- **对比**：Triage-Assist-AI 用 Groq/Gemini 云端 API——**这是诊途在医疗合规上的根本优势**。

### 创新点 3：双向融合 + 证据核验
- **稀缺性**：同类通常是"模型给答案"，诊途是"模型做**被约束的翻译与措辞**"，且每条证据过 4 规则白名单。
- **证据**：SYNONYMS 47 组登记同义形；`evidenceMatchesKeyword()` 四规则；122→150 条主集锁定。
- **对比**：同类无等价的结构化证据核验。

### 创新点 4：完整评测门禁（该赛道唯一）
- **稀缺性**：**同类无一具备**"冻结盲测（20）+ 对抗红队（24）+ SHA-256 防漂移 + 失败白名单 + 覆盖率门禁"完整体系。
- **证据**：150 条主集、20 条 held-out、24 条红队、16 条 AI 必要性探针、12 文件指纹、87 单测、CI。
- **对比**：Triage-Assist-AI 仅模型指标；Intelligent-guidance 无评测。

## 六、诚实的短板（不回避，反而增强可信度）

对比中诊途也暴露了**弱项**，写进材料时**主动声明**比被评审发现更好：

1. **演示物料缺失**：无演示视频、无答辩 PPT、无正式技术报告（对比 Intelligent-guidance 三者齐全）。→ 这是可快速补齐的。
2. **场景定位不同**：Triage-Assist-AI 面向**院内护士**（ESI 分级、候诊队列、再评估），诊途面向**院前患者自助导诊**。二者不是替代关系，**不应声称"比它强"**，而应说明"面向不同环节"。
3. **临床验证缺失**：两者都声明"非医疗器械、未经临床验证"——这是该赛道的共同边界，不能作为差异点。
