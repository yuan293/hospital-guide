# 院内智导 0.4.2

**开源许可证：Apache-2.0**——本仓库全部内容（代码、示例数据、文档、测试与评测集）统一采用 Apache-2.0，见根目录 `LICENSE`；两个本地模型同为 Apache-2.0，许可原文见 `data/model-licenses/`；第三方资源的许可与义务见 `THIRD_PARTY_NOTICES.md`。

本机运行的医院挂号与导诊工程原型。首页给患者两个入口：**直接挂号**（自己知道挂哪个科，选科室看位置与就诊提示）与**不确定挂哪科**（描述不适，系统给出科室方向）。导诊流程包含安全确认、多轮补充信息、风险分流、科室匹配、依据展示、科室目录、摘要下载和可选的 Ollama 症状标准化。

0.4.2新增**模拟挂号演示流程**：两个入口在科室确定后都可点"确认挂该科室"，依次完成 确认科室 → 选择号别（普通号／专家号，模拟费用）→ 模拟支付（60秒倒计时；点"我已付款成功"即演示挂号成功并展示科室、位置、号别与模拟单号，点"未付款"或超时则挂号失败、可重新挂号）。该流程是**纯前端演示**：不接入任何真实支付、不产生真实订单，对话框内全程显著标注"模拟"，真实挂号仍须通过医院官方渠道；急诊分流与弃权/转人工结局不提供挂号入口。

0.4.1新增**关怀模式（适老化）**：页面顶部提供一键开关，开启后全局放大字号、提高对比度、加大按钮触控区域，偏好只记在本机浏览器；导诊中选择"65岁及以上"时，会经一次知情同意询问是否开启，拒绝后不再打扰，也可随时用顶部开关自行切换。该功能只作用于展示层——"65岁及以上"提交给导诊引擎时仍按成人（adult）处理，不改变任何规则、数据结构与评测结果；我们刻意不采用摄像头估龄或操作行为推断，以避免隐私风险、误判与对用户的冒犯。

0.4 面向大众重做入口与流程。首页改为**两个入口**：① **我要直接挂号**——已经知道挂哪个科，直接选科室，系统给出楼层、位置、接诊范围与就诊提示（原型没有号源，明确说明挂号要走医院官方渠道）；② **不确定挂哪科**——描述不适，系统给出科室方向。目标是把患者的决策成本降到最低，而不是把问诊搬到线上。

导诊流程新增**安全确认**：主诉命中路径锚点（上腹、剑突下、胃痛、胃部、反酸）后，先问3项**红旗征**排除必须尽快处理的情况（消化道出血征象、心源性胸痛征象、持续剧痛或腹部僵硬），再进入科室决策。红旗征阳性与风险闸门同级，直接升级急诊分流；回答“不确定／说不清”按转人工处理，不允许当作阴性继续推荐科室；安全确认与红旗征判定都不会调用模型，模型也不能覆盖升级结论。问题库仍以 HL7 FHIR R4 Questionnaire 存储，新增 `probe-pathway`／`probe-order`／`option-escalate`／`option-narrative` 扩展与根级路径定义，启动时 fail-closed 校验（路径 id 存在、路径内顺序唯一、每个选项都要有措辞、红旗征选项不得带科室权重）。评测集含81条案例（含安全确认3条、红旗征3条）。

0.3.2两项打磨：首页新增**“30秒自动演示”入口**——一键自动走完安全提问、鉴别追问（可看到并列科室与信息增益说明）到科室建议，任何人工点击立即接管，演示强制走规则流程以避免模型冷加载等待；评测标签引入 fail-closed 的**等价安全结局 anyOf**——对模糊主诉，模型老实返回空症状时转人工、模型脑补但证据全部失验时弃权，两条都是“不推荐科室并升级处理”的安全路径（分别为7B与1.5B实测行为），此前标签只承认后者，导致更克制的7B反而记一次失败；anyOf 只允许 human/uncertain 且科室为 null，不可能把错误推荐判为通过。

0.3.1在0.3基础上：鉴别问题库从3个扩展到**6个 probes**（新增腰痛→骨科/泌尿、头晕耳鸣→神经/耳鼻喉、皮疹眼痒→皮肤/眼科三组高频鉴别），并让追问选择**可解释、可核验**——问题卡片直接展示“当前哪几个科室证据相同、该问题最多能拉开几分差距”，逐轮评测轨迹同步记录并列科室（leaders）与增益分（gain）；案例集扩展到75条。

0.3新增两项能力：**信息增益动态追问**（安全槽补齐后，按配置的鉴别问题库 probes 选择对当前平局科室区分度最大的问题，最多2问；零候选时先问不适部位）与**存疑弃权机制**（追问后仍无法定位、规则与模型给出不一致的具体科室、或模型证据全部未通过原文核验时，返回 uncertain 转人工，而不是硬猜）。同时新增 legacy 固定追问消融组、弃权率/分歧率/证据失效率/平均决策轮数指标。模型仍只在终态决策前调用一次；追问轮与急症分流不会调用模型。

0.2的可替换医院JSON、来源与年龄约束校验、规则与本地模型对照、逐轮轨迹和网页“效果评测”保持不变。使用说明见 `data/README.md` 和 `data/evaluation/README.md`。

**所有院区、地址和科室资料均为虚构演示数据。规则未经医护专业审核和临床验证，不能用于真实医疗决策。系统不作疾病诊断，也不提供处方。**

## 启动

需要 Node.js 20 或以上，不需要 npm install。Windows 双击 `start.cmd`，保持窗口打开，在浏览器中打开窗口给出的地址，默认 `http://127.0.0.1:3210`。端口被占用时自动尝试下一个端口。

也可以在项目目录执行：

```sh
npm start
```

只监听本机 127.0.0.1，没有公网部署、登录系统或院方接口。关闭启动窗口或按 Ctrl+C 停止服务。

## 在新电脑上使用（给朋友）

不复制任何本机文件，从零开始只需以下步骤。**基础功能（导诊规则、安全闸门、模拟挂号、关怀模式）不需要下载大模型。**

1. **安装 Node.js 20 或以上版本**：到 https://nodejs.org 下载 LTS 版一路下一步安装。验证：打开命令行输入 `node -v`，显示 v20 以上即可。
2. **获取项目**（二选一）：
   - 会用 Git：`git clone https://github.com/yuan293/hospital-guide.git`
   - 不会 Git：打开仓库页面，点绿色 **Code** 按钮 → **Download ZIP**，解压到任意文件夹。
3. **在项目目录打开命令行**：进入解压/克隆出的文件夹（能看到 `package.json` 和 `start.cmd` 的那一层），点击文件资源管理器的**地址栏**，输入 `cmd` 后回车，弹出的黑窗口即位于项目目录。（也可以在文件夹空白处 Shift+右键 →「在终端中打开」。）
4. **启动**：Windows 双击 `start.cmd`（或在该窗口执行 `npm start`），保持窗口打开，浏览器访问窗口提示的地址，默认 `http://127.0.0.1:3210`。**不需要执行 `npm install`**——项目刻意零依赖。
5. **（可选）启用本地双模型**：模型未安装时网页自动使用规则模式并明确提示，不影响基础体验。确需模型时，在第 3 步的同一命令行窗口执行：

   ```sh
   npm run models:setup   # 下载官方 Ollama v0.34.4（约1.46GB），SHA-256 校验不符会拒绝安装，仅支持 Windows x64
   npm run models:pull    # 下载 qwen2.5:7b 与 qwen2.5:1.5b（约5.7GB），有进度显示
   npm run models:check   # 可选：用3条输入冒烟验证模型可用
   ```

   预留至少 15GB 磁盘空间；两条命令均为一次性下载，**之后可离线使用**，中途失败重跑同一命令即可续上。下载源在 GitHub/Ollama 官方，国内网络如遇失败请开启网络加速或代理后重试。macOS/Linux 不使用 setup 脚本：先在 https://ollama.com 安装官方 Ollama，执行 `ollama pull qwen2.5:7b` 与 `ollama pull qwen2.5:1.5b`，再 `npm start`，项目会自动识别本机 11434 服务。

常见问题：提示"npm 不是内部或外部命令"说明 Node.js 未安装或安装后未重新打开命令行窗口；浏览器打不开地址先确认启动黑窗口仍在运行；本服务只能在运行项目的电脑本机访问，不是可分享的公网网址；所有医院与科室数据均为虚构，不能用于真实就医。

## 评委复现指南

仅需 Node.js 20+，**不需要 npm install**，全程只监听本机 127.0.0.1。路径 A 不下载模型即可验证全部规则引擎、安全闸门与界面功能；路径 B 复现双模型结果；路径 C 供现场断网备用。

### 路径 A：免模型快速验证（约3分钟，零下载）

```sh
git clone https://github.com/yuan293/hospital-guide.git
cd hospital-guide
npm test      # 预期：tests 51 / pass 51 / fail 0
npm run verify
npm start     # 浏览器打开 http://127.0.0.1:3210
```

`npm run verify` 是 fail-closed 门禁链（单元测试 → 数据 fail-closed 校验 → 无模型评测），任一项不达标即以退出码 1 失败；输出最后一行打印"全部通过（快速链）"即复现成功。当前仓库基线：

| 检查项 | 预期结果 |
|---|---|
| 单元测试 | 51/51 通过，0 失败 |
| 数据 fail-closed 校验 | 通过（FHIR R4 Questionnaire 结构、来源与年龄约束） |
| rules 组（legacy 固定追问，消融对照） | 56/64；8 条未中全部是 HG-039～HG-046 口语表达老基线，锁定在 failedIds 白名单门禁内 |
| dynamic 组（安全确认＋信息增益动态追问） | **66/66 全通过** |
| 急诊红旗征召回（两组相同） | 12/12，漏诊 0 |
| 普通症状误触发急诊 | 0（rules 0/52，dynamic 0/54） |
| dynamic 组自动推荐科室命中 | 34/34 |

浏览器内可现场核验：两个入口、"▶ 30秒自动演示"、"上腹痛、反酸"的红旗征安全确认、紧急情况拦截、关怀模式（含65岁及以上知情同意）、以及模拟挂号全流程（确认科室→普通号/专家号→60秒支付倒计时→成功展示科室信息或超时重新挂号）。网页"效果评测"页展示各指标分子分母、失败案例、逐轮追问轨迹（leaders/gain）与报告 JSON 下载。评测报告记录12个指纹文件的 sha256，代码或数据一旦变动会标记过期，杜绝报告与代码不符。


### 路径 C：现场完全离线（无网络备用方案）

模型程序与权重均位于项目内 `.runtime/`（已被 `.gitignore` 忽略，不随仓库分发）：将该目录整体拷贝到仓库同级路径后 `npm start` 即为完整双模型环境，断网可用。不入库的原因：含约7.2GB二进制与本机运行日志，且 Ollama 与 Qwen2.5 各有许可证、应通过官方渠道按固定版本与哈希获取，直接再分发二进制反而有合规风险。

### 用户调研证据

“患者是否真的普遍分不清科室”的一手证据见 [docs/院内智导-问题与场景价值-调研正文.docx](docs/院内智导-问题与场景价值-调研正文.docx)：匿名问卷 N=88，94.3% 的受访者近一年有过“不知道挂什么科”的经历，92.0% 有过挂错号/退号重挂经历，89.8% 接受“拿不准转人工、急症提示急诊”的产品边界。仓库仅公开聚合后的报告正文，不上传原始答卷，以保护开放题中的个人表述。

## 快速体验

1. 打开页面先看到两个入口：点**我要直接挂号**，搜索“消化内科”并选中，会给出楼层、位置、接诊范围和就诊提示；没有接入真实号源这一点会写明白。
2. 或者点**不确定挂哪科**，选“咳嗽、发热”示例，点“开始导诊”。
3. 回答风险、年龄和严重程度问题；当证据并列或无法定位时，系统会追问一个与当前症状相关的鉴别问题，并说明为什么问这个问题（并列科室与增益分）。
4. 不确定的情况可以点“▶ 30秒自动演示”，自动走一遍安全确认 → 鉴别追问 → 科室建议的完整链路，随时可人工接管。
5. 查看建议、示例位置和来源，可下载一份本次摘要；若系统回答“存疑弃权”，说明证据不足或规则与模型结论冲突，应转人工导诊。
6. 用“上腹痛、反酸”示例可以观察到**安全确认**：系统会先问三项红旗征，回答“有”会直接转向急诊，回答“不确定”会转人工。
7. 重新开始，选择"紧急情况"示例，观察普通流程被停止。
8. 在科室目录搜索关键词、筛选类别、查看科室详情。
9. 点顶部**关怀模式**开关可切换大字号、高对比、宽触控界面；导诊年龄问题选择"65岁及以上"时会看到一次知情同意提示（拒绝后不再弹出）。
10. 在直接挂号选中科室、或导诊得到科室建议后，点**确认挂该科室**，走完 确认 → 普通号/专家号 → 60秒模拟支付：点"我已付款成功"可看到挂号成功页（模拟单号与科室信息），点"未付款"或等倒计时结束则提示挂号失败、需重新挂号。全程为前端演示，不产生真实支付。

## 本地大模型

支持两个本地模型：`qwen2.5:7b` 用作导诊主模型，`qwen2.5:1.5b` 用作轻量对照。安装后页面自动选用7B，运行设置可以切换模型或回到不调用模型的规则演示模式。只记忆模型选择，不保存对话。

模型运行程序位于 `.runtime/ollama`，模型文件位于 `.runtime/models`，均被Git忽略。启动项目时会自动检查并启动本机服务，关闭网页不会停止该后台服务，模型空闲5分钟后释放显存。关闭Ollama进程后，再次启动项目会重新启动它。

在新电脑上首次准备环境：

```sh
npm run models:setup
npm run models:pull
```

安装脚本适用于Windows x64，从GitHub官方发布下载 Ollama v0.34.4 并校验SHA-256；再从Ollama官方仓库下载模型。运行程序下载约1.46GB，模型合计约5.7GB，解压后额外需要磁盘空间。首次启动Ollama会在用户目录 `.ollama` 生成本机密钥，云端功能通过 `OLLAMA_NO_CLOUD=1` 禁用。已存在的外部Ollama服务不会被重配，其模型目录与云端开关以该服务的配置为准。

实际模型版本、摘要和大小由安装脚本记录到 `data/installed-models.json`；模型随附许可保存在 `data/model-licenses/`。公开项目时不上传 `.runtime` 和个人密钥。

本机 Ollama 默认地址为 `http://127.0.0.1:11434`。可以通过环境变量 `OLLAMA_URL` 修改为另一个本机 HTTP 地址，应用不允许配置远程模型地址。模型请求最长等待90秒，首次加载通常比后续调用慢；失败时提示并回退到规则模式。结果显示本次实际使用的模型、耗时和词语映射，顶部模型名仅表示当前选择。

模型仅将口语描述映射为配置中的症状词，并返回原文证据。程序检查词表、2–8字短片段与原文连续引用（长主诉中引用整句不予采信），但这些检查**不能证明医学语义正确**。风险规则不受模型输出控制，命中紧急分流时不调用模型。

0.3起，模型结果还要通过两道分歧闸门：规则流程与模型分别收敛到不同的具体科室时返回 `uncertain`（reasonCode=`model_conflict`）；模型自报了症状但没有任何一条通过词表与原文连续片段核验、且规则本在等待模型救援时返回 `uncertain`（reasonCode=`evidence_invalid`）。模型永远不能把结果从急诊改为普通科室。

### 规则与模型的分工：模型为什么不可被规则替代

本项目不是“用大模型替换规则”，而是让两者承担各自不可替代的职责，并用一组消融对照给出证据（原始数据：`data/evaluation/runs/2026-09-25T07-44-20-106Z.json`；任何人执行 `npm run evaluate:models` 可复算）。

**规则负责安全底线。** 红旗征急诊确认、“当前肯定存在”上下文判定（否定连用、病史、家属、未然情态）、儿童接诊约束等全部由确定性规则执行：命中红旗征时直接升级急诊、不调用模型，模型输出永远不能把急诊结论降级为普通科室。全部六个评测组（含两个模型组）急诊召回均为 12/12、急诊误触发为 0。

**模型负责人类表达的多样性。** 评测集专门设计了 8 条口语化主诉（HG-039~046），语义等同配置词表但不逐字匹配。纯规则模式下这 8 条全部无法命中词表，结局都是“转人工”（该组 56/64）；7B 模型组 8 条全部正确映射到目标科室（该组 65/65，实际推荐科室 32/32 全部正确）：

| 口语主诉（案例原话） | 目标科室 | 纯规则基线 | qwen2.5:7b | qwen2.5:1.5b |
| --- | --- | --- | --- | --- |
| 肚子疼了两天 | 消化内科 | 转人工 | 正确 | 正确 |
| 脑袋疼了两天 | 神经内科 | 转人工 | 正确 | 正确 |
| 嗓子疼，持续两天 | 耳鼻喉科 | 转人工 | 正确 | 弃权转人工 |
| 拉肚子三天 | 消化内科 | 转人工 | 正确 | 正确 |
| 眼睛发干 | 眼科 | 转人工 | 正确 | 正确 |
| 小便的时候疼 | 泌尿外科 | 转人工 | 正确 | 正确 |
| 腰部疼痛两天 | 骨科 | 转人工 | 正确 | 正确 |
| 皮肤很痒 | 皮肤科 | 转人工 | 正确 | 正确 |

1.5B 模型在这 8 条上答对 7 条，“嗓子疼”一条选择弃权；该组全部 4 条未通过案例（HG-018/020/041/051）无一给出错误科室，全部是 `uncertain` 弃权转人工——实际给出推荐的 31 条中 31 条科室正确（覆盖率 96.9%、推荐准确率 100%）。这说明架构对模型质量是鲁棒的：**弱模型不会变得危险，只会变得保守**。需要说明的是，无模型 dynamic 组的 66/66 分母不含这 8 条（它们按模式适配标记为跳过），这 8 条就是专门为检验模型开放语言理解能力设置的案例。

这一分工与用户调研相互印证：问卷开放题中的真实表述（如“腰部疼但不知道是骨头还是筋”“上厕所老是拉血”）与这 8 条挑战案例同质，而 71.6% 的受访者最终仍依赖导诊台人工确定科室——纯规则系统对这类表达的结局同样是“转人工”。模型补上的，正是规则无法穷举的开放语言理解环节，而非诊断决策本身；规则与模型结论冲突、或模型证据通不过原文核验时，系统照样弃权让人接管。一句话：**规则守住安全底线，模型接住人类表达的多样性，二者不一致时由人接管。**

## 标签与规则依据

所有标签均为演示配置，但编写时逐类对照了公开权威依据做合理性核对，避免"拍脑袋"式虚构。映射与取舍由团队完成，**这不等于经过医护专业审核或临床验证**（见"当前限制"）。

鉴别追问问题库以 HL7 FHIR R4 `Questionnaire` 资源结构存储（`data/hospital.json` 的 `questionnaire` 字段）：问题与选项使用 FHIR 原生 `linkId`/`text`/`type`/`answerOption`/`valueCoding` 字段，问题类型、科室权重、锚点症状、鉴别科室对与来源等工程参数通过扩展字段表达（扩展 URL 前缀见文件内 `description`）。服务启动时先按 FHIR 结构 fail-closed 校验，再适配为内部评分结构；`/api/config` 同时返回原始 Questionnaire 资源，便于第三方系统直接复用问题库。问卷引用的每个自定义扩展都在仓库内发布了对应的 `StructureDefinition` 结构定义（见 [`StructureDefinition/`](StructureDefinition/) 目录与索引页），canonical URL 含 GitHub 网页路由段（`…/blob/main/StructureDefinition/<尾名>`），与仓库文件一一对应，直接点击问卷中的扩展 URL 即可在 GitHub 页面核验定义，索引页同时给出 raw JSON 机器可读入口；文件由 `npm run fhir:export` 从问卷自动生成，单测中的防漂移门禁保证数据里出现的每个扩展 URL 都有对应定义文件。问卷资源本体对应 `Questionnaire/hospital-guide-probes`。

## 当前限制

- 风险规则有限，中文否定、时间、第三方叙述等解析并不完整，可能漏判或误判。应答“没有紧急表现”不代表排除急症。
- 动态追问只覆盖配置好的少量鉴别问题（当前6个鉴别 probes：发热→呼吸/神经/耳鼻喉、腹痛→消化/泌尿、腰痛→骨科/泌尿、头晕→神经/耳鼻喉、皮疹眼痒→皮肤/眼科，外加1个不适部位定位问题），问题选择是确定性的配置规则，增益分是“某回答能在并列科室间拉开的最大权重差”的工程化代理值，不是学习得到的提问策略或概率意义上的信息增益，也不是完整RAG；未配置锚点或科室对的平局仍直接转人工。
- 安全确认目前只有“上腹痛”一条（3项红旗征），问题顺序与升级目标都是演示配置。锚点是词表匹配：口语化主诉（如“肚子疼”）不会激活安全确认，而是走部位定位与鉴别追问；红旗征回答“不确定／说不清”一律转人工，会推高人工转接率。
- “直接挂号”入口只提供科室位置与就诊提示；0.4.2 起提供的挂号与支付是**纯前端模拟流程**（模拟号别、模拟费用、60秒倒计时、模拟单号），原型没有真实号源、没有排班，也没有对接任何院内系统或支付通道，不产生真实订单，挂号本身要走医院官方渠道。模拟对话框与成功页都明确标注"模拟"，不假装能完成真实挂号。
- “存疑弃权”基于规则化的分歧与证据核验条件，不等于经过校准的医学置信度；弃权率高低不直接代表系统好坏。
- 科室匹配采用关键词和可选模型标准化；页面中的挂号/支付仅为前端模拟演示，没有真实医生排班、号源或支付通道。
- 孕产期、婴儿、用药以及信息不足的情况转人工；儿童规则仅为虚构配置示例。
