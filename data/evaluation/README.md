# 可复现工程评测

数据集 `hospital-guide-synthetic-v1`（2026-09-25.5）含90条案例：54条已知行为回归和36条扩展压力案例。其中6条为安全确认与红旗征案例（`安全确认`／`红旗征`两个分类）。全部为AI辅助编写的合成描述，无真实患者数据，也未经医护审核。所有案例对开发者可见，不能宣称独立盲测或临床准确率。部分口语示例在提示词中出现，这一点影响对泛化能力的判断。

案例可带 `modes` 字段（`rules`/`model`/`workflow`/`dynamic`）声明只适用于哪些评测模式；不适配的模式标记为“本模式不适用”，不计入该组指标分母。`expected.reasonCode` 可选，用于断言弃权原因（`ambiguous`/`unlocated`/`model_conflict`/`evidence_invalid`）。

`expected.anyOf` 可选，声明多个**等价安全结局**：同一输入在不同模型上可能以不同但都安全的方式收尾（如 HG-068 模糊主诉——模型老实返回空症状时规则零候选转人工 human/unmatched，7B实测；模型脑补但证据全部失验时弃权 uncertain/evidence_invalid，1.5B实测），两条都满足“不推荐科室并升级处理”的不变量。anyOf 为 fail-closed 设计：至少两个结局、每个只能是 human/uncertain 且 department 为 null、主预期必须被其覆盖，因此不可能用它把错误推荐判为通过；新增此类标签必须在 `labelNote` 写清两条路径各自的真实来源。

## 执行

```sh
npm run data:validate
npm test
npm run evaluate
npm run evaluate:models
```

最后一个命令顺序运行：legacy规则基线、无模型动态追问、7B模型辅助、7B完整多轮（动态追问）、1.5B模型辅助、1.5B完整多轮。需要本机安装这两个模型，不会自动下载。也可使用 `node scripts/evaluate.js --models=qwen2.5:7b`。

- `rules`（legacy基线）：直接输入案例提供的回答，固定追问 risk→age→duration→severity，平局与零候选直接转人工；作为消融对照保留。
- `dynamic`：默认策略，不强制询问 duration；安全槽之后先完成命中的安全确认（上腹痛：3项红旗征，按 `probe-order` 顺序，阳性直接升级急诊、“不确定”转人工），再按信息增益提出鉴别问题（预算2问），零候选先问部位；追问后仍无法判定则返回存疑弃权。不调用模型。
- `model`：一次性输入全部回答，生产流程按风险闸门决定是否调用真实模型做症状标准化，含规则/模型分歧弃权。
- `workflow`：从空回答开始，逐一补充案例提供的回答（含 probes 答案），动态追问完成后在终态调用至多一次模型；风险命中立即中止，追问后显式弃权（ambiguous/unlocated）也不调模型。没有提供的答案保持缺失，因此零候选口语压力案例只在 rules/model 下评测。
- 四者共享 `lib/flow.js` 与网页决策逻辑。这是症状标准化对照、追问消融及交互流程验证，不是独立算法的医学质量比较。
- 交互组（`dynamic`／`workflow`）按案例提供的回答逐轮推进，轮次上限14（安全槽3＋安全确认3＋追问3＋余量）；案例没有提供的答案保持缺失，流程会停在对应追问上，因此这类案例的 `expected` 必须写成该追问本身。
- 评测不使用网页用户会话，网页也不能提交任意病例到评测文件。

结果在 latest.json 和 runs/ 时间戳文件中保存；网页“效果评测”可以逐条核验和下载JSON。只展示实际运行组，模型缺失明确标记为跳过。代码、数据、提示词的SHA-256指纹用于发现过期结果；修改后须重跑。无模型评测会覆盖最近结果，但历史保留。

## 指标

- 科室命中率：正确推荐科室数 / 预期应推荐科室数。转人工不能算科室命中。
- 急诊识别率：正确急诊分流数 / 预期急诊数，并单列漏分流数。
- 非急诊误触发率：非急诊标签中实际急诊数 / 非急诊标签数。
- 人工转接率：实际人工转接数 / 全部实测案例数，不以越低越好。
- 应转人工识别率：正确人工转接数 / 预期人工转接数。
- 存疑弃权率：实际 uncertain 数 / 全部实测案例数；弃权是安全特性，不以越低越好。
- 规则/模型分歧弃权率：reasonCode 为 model_conflict 的案例占比。
- 模型证据失效弃权率：reasonCode 为 evidence_invalid 的案例占比。
- 平均决策轮数：该模式每条案例从开始到终态的平均交互轮数（含安全槽与动态追问）。
- 全部符合预期：状态、科室、所需追问及可选 reasonCode 同时符合标签（或命中 anyOf 等价安全结局）的数量 / 全部实测案例数。
- anyOf 与分组指标：anyOf 只影响“是否符合预期”的判定；分组指标（应转人工识别率等）的分母仍按主预期 `status` 归类。因此同一条 anyOf 案例在不同模型上可能记入不同路径指标——如 HG-068 主预期为人工：7B 实际 human 计入人工识别，1.5B 实际 uncertain 计入存疑弃权率而非人工识别；两条路径在“全部符合预期”中均为通过。
- 模型调用成功、失败、原文证据以及每条完整逐轮轨迹。
- 单次顺序测试的平均与P95耗时，包含冷启动，不代表生产并发性能。零分母显示无样本。

默认命令在已知行为回归失败、执行错误、模型调用失败或请求的模型缺失时返回非零。扩展压力案例失败会保留并展示，不阻止发布结果；加 `--strict` 要求全部案例符合预期。

## 扩展与维护

新增案例填写稳定 id、suite、category、input 和 expected，记录来源及标注依据。修改预期不得仅为让实现通过；已知问题应保留到修复并复核。当前没有独立医生标注集、用户试用数据或跨医院验证；后续应分离开发与独立评测数据。

本目录、校验器、评测器与合成评测集是可复用的工程成果，随本仓库统一以 Apache-2.0 公开（见仓库根目录 `LICENSE`）。合成案例为团队自建，不含真实患者数据；第三方资源的许可与义务见 `THIRD_PARTY_NOTICES.md`。
